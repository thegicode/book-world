# 🚀 기술 및 빌드 프로세스 개선 로드맵

현재 프로젝트의 기술적 완성도를 높이고 유지보수성을 강화하기 위한 단계별 개선 제언입니다.

## 🛠️ 단기 개선 과제 (DX & 가독성)

- [x] **절대 경로 별칭(Path Aliases) 도입**
    - **내용:** `../../../`와 같은 복잡한 상대 경로를 `@/scripts/model`과 같이 간결한 절대 경로로 대체합니다.
    - **이점:** 파일 위치 이동 시 경로 수정이 불필요하며 코드 가독성이 대폭 향상됩니다.
    - **방법:** `tsconfig.json`의 `paths` 설정 및 `esbuild` 별칭 설정을 활용합니다.

- [x] **빌드 스크립트 모듈화 및 워크플로우 통합**
    - **내용:** `package.json`의 복잡한 `scripts`를 별도의 TypeScript 빌드 스크립트(`scripts/build.ts`)로 분리합니다.
    - **이점:** 빌드 순서(HTML -> CSS -> JS -> Image)를 명확히 제어하고 에러 처리를 강화할 수 있습니다.

## 🧪 품질 및 안정성 강화

- [x] **테스팅 프레임워크(`Vitest`) 도입**
    - **내용:** `esbuild`와 호환성이 뛰어난 초고속 테스팅 도구 `Vitest`를 사용하여 핵심 로직을 검증합니다.
    - **이점:** `FavoriteModel`, 데이터 마이그레이션 등 비즈니스 로직의 무결성을 수초 내에 자동 검증할 수 있습니다.

- [ ] **Git Hooks를 활용한 사전 품질 관리 (`Husky` + `lint-staged`)**
    - **내용:** `git commit` 시점에 `eslint`와 `tsc` 타입 체크를 자동으로 실행합니다.
    - **이점:** 문법 오류나 타입 에러가 있는 코드가 저장소에 커밋되는 것을 방지하여 코드 품질을 상시 유지합니다.

## ✨ 아키텍처 고도화

- [ ] **컴포넌트 템플릿 처리 방식 개선 (`lit-html` 등 고려)**
    - **내용:** 현재의 문자열 기반 템플릿 처리를 더 선언적이고 안전한 방식(`lit-html` 등 초경량 라이브러리)으로 전환을 검토합니다.
    - **이점:** 복잡한 데이터 바인딩 시 코드의 안전성을 높이고 선언적인 UI 작성이 가능해집니다.
