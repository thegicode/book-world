## 아키텍처 개선 제안 (2026년 2월 13일)

이 프로젝트는 이미 매우 높은 수준의 아키텍처를 갖추고 있다는 점을 말씀드리고 싶습니다. 프레임워크 없이 웹 표준을 기반으로 구축되었음에도 불구하고, 코드 분할, 경량 상태 관리, 컴포넌트 기반 설계 등 현대적인 개발 방법론이 훌륭하게 적용되어 있습니다.

현재의 견고한 구조를 더욱 발전시키기 위해 다음과 같은 두 가지 개선 사항을 제안합니다.

### 1. CSS 디자인 토큰 시스템 도입 (High-Impact)

#### 문제점
현재 다수의 SCSS 파일(`_book-description.scss`, `setting.scss` 등)에 색상, 폰트 크기, 간격 등을 나타내는 값들(예: `#767676`, `12px`)이 직접 하드코딩되어 있습니다. 이는 '매직 넘버'로, 다음과 같은 문제를 야기합니다.

*   **디자인 불일치**: 동일한 의미의 색상이나 간격이 파일마다 다른 값으로 사용될 수 있습니다.
*   **유지보수의 어려움**: 전체 디자인 시스템의 색상이나 폰트 크기를 변경하려면 수많은 파일을 찾아 수정해야 합니다.
*   **확장성 저하**: 다크 모드와 같은 새로운 테마를 적용하기가 매우 어렵습니다.

#### 개선 방안
프로젝트 전역에서 사용될 디자인 토큰을 **CSS Custom Properties(CSS 변수)** 로 정의하고, 이를 모든 컴포넌트에서 사용하도록 변경하는 것을 제안합니다.

1.  **전역 스타일시트에 토큰 정의**:
    `_reset.scss` 또는 별도의 `_tokens.scss` 파일의 `:root` 선택자 안에 색상, 폰트, 간격 등에 대한 변수를 정의합니다.
    ```css
    /* 예시: _tokens.scss */
    :root {
        --color-text-primary: #333;
        --color-text-subtle: #767676;
        --font-size-small: 12px;
        --spacing-unit: 8px;
    }
    ```

2.  **컴포넌트에서 토큰 사용**:
    각 SCSS 파일에서 하드코딩된 값을 CSS 변수로 대체합니다.
    ```scss
    /* 변경 전 */
    color: #767676;
    font-size: 12px;

    /* 변경 후 */
    color: var(--color-text-subtle);
    font-size: var(--font-size-small);
    ```

#### 기대 효과
*   **디자인 일관성 확보**: 프로젝트 전체의 시각적 통일성을 보장합니다.
*   **유지보수성 향상**: 토큰 파일만 수정하면 전체 애플리케이션의 디자인을 쉽게 변경할 수 있습니다.
*   **확장성 증대**: 다크 모드 등 새로운 테마를 손쉽게 추가할 수 있습니다.

### 2. 시맨틱 리스트 구조 강화 (Medium-Impact)

#### 문제점
`SearchResult` 컴포넌트는 `book-item` 목록을 `<div>` 컨테이너 안에 렌더링하고 있습니다. 시맨틱 HTML 관점에서 볼 때, 이는 단순한 그룹핑일 뿐 '목록'이라는 의미를 전달하지 못합니다.

#### 개선 방안
책 검색 결과와 같이 반복되는 아이템 목록은 `<ul>` 또는 `<ol>` 태그로 감싸고, 각 아이템은 `<li>` 태그로 만드는 것이 웹 표준에 부합합니다.

1.  **`SearchResult.ts` 수정**: `createItem` 함수 등에서 `<book-item>` 커스텀 엘리먼트를 `<li>` 태그로 감싸서 생성하도록 변경합니다.
2.  **컨테이너 태그 변경**: `data-list-container` 속성을 가진 `<div>`를 `<ul>`로 변경합니다.

    ```typescript
    // SearchResult.ts 예시
    private createItem(book: IBook): HTMLElement {
        const li = document.createElement('li'); // li 요소 생성
        const bookItem = new BookItem(book);
        li.appendChild(bookItem);
        return li;
    }

    // 템플릿의 data-list-container를 <ul>로 변경
    ```

#### 기대 효과
*   **웹 접근성 향상**: 스크린 리더 사용자가 "총 N개의 아이템이 있는 목록"으로 구조를 명확하게 인지하고 탐색할 수 있게 됩니다.
*   **검색 엔진 최적화(SEO) 개선**: 검색 엔진이 콘텐츠의 구조를 더 잘 이해하게 되어 SEO에 긍정적인 영향을 줄 수 있습니다.
