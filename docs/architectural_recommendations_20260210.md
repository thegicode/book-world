# Book World 프로젝트 아키텍처 개선 제안

**작성일**: 2026년 2월 10일 화요일

## 현재 아키텍처 진단

### 강점

*   **명확한 관심사 분리 (SoC)**: 프론트엔드(`app`)와 백엔드(`server` - BFF)의 역할이 명확히 분리되어 있으며, 프론트엔드 내에서도 페이지, 컴포넌트, 모델, 서비스 등 역할별로 모듈화가 잘 되어 있어 구조가 명확하고 확장성이 좋습니다.
*   **최신 개발 도구 활용**: TypeScript, esbuild, Sass 등 효율적이고 안정적인 최신 개발 도구를 사용하여 개발 생산성과 코드 품질을 높이고 있습니다.
*   **성능 중심의 빌드 전략**: `esbuild.config.js`에서 페이지별로 JavaScript 번들을 분리(Code Splitting)하는 전략을 채택하여, 사용자가 각 페이지에서 필요한 최소한의 코드만 다운로드하게끔 설계된 점은 매우 훌륭한 성능 최적화 사례입니다.
*   **컴포넌트 기반 아키텍처**: 프레임워크 없이도 Custom Elements(`BaseItemComponent`)를 기반으로 재사용 가능한 컴포넌트를 구축하여 애플리케이션의 유지보수성을 높였습니다.
*   **효율적인 무한 스크롤**: `SearchResult` 컴포넌트에서 `IntersectionObserver`를 활용한 무한 스크롤 구현은 긴 목록을 다루는 가장 효율적이고 현대적인 접근 방식입니다.

## 아키텍처 개선 제안 (To-Do List)

현재의 탄탄한 구조를 바탕으로, 다음 네 가지 영역에서 아키텍처를 한 단계 더 발전시킬 수 있습니다. 각 항목은 체크박스로 관리할 수 있습니다.

### 1. 컴포넌트 렌더링 및 DOM 최적화

- [x] **HTML 템플릿 빌드 시 인라이닝 도입**:
    -   `BaseItemComponent`가 런타임에 `fetch`로 HTML 템플릿을 가져오는 대신, 빌드 시점에 esbuild 플러그인 또는 스크립트를 사용하여 HTML 템플릿 내용을 JavaScript 파일 내 문자열 변수로 삽입합니다.
    -   **기대 효과**: 런타임 네트워크 요청 제거, 초기 렌더링 시작 시간 단축, 초기 로딩 성능 향상.
- [x] **파괴적인 DOM 조작 개선**:
    -   `this.listContainer.innerHTML = "";`와 같은 방식을 지양하고, 자식 노드를 안전하게 제거하는 방식으로 변경합니다.
    -   컴포넌트 인스턴스에 `destroy()`와 같은 메서드를 구현하여 이벤트 리스너 해제 등 안전한 소멸 과정을 보장합니다.

### 2. 상태 관리 아키텍처 고도화

- [x] **경량 중앙 집중식 스토어(Store) 도입**:
    -   애플리케이션의 핵심 상태(예: 검색 결과, 사용자 설정)를 한 곳에서 관리하는 간단한 '스토어' 객체를 구현합니다.
    -   스토어는 상태 변경 시 이벤트를 발행하고, 컴포넌트들은 스토어를 구독하여 필요한 부분만 다시 렌더링합니다.
    -   **기대 효과**: 데이터 흐름 예측 가능성 향상, 단일 진실 공급원 확보, 유지보수성 개선.

### 3. 웹 접근성 강화 (WCAG 2.1 AA)

- [ ] **시맨틱 랜드마크 보장**:
    -   `<main>` 요소를 사용하여 페이지의 핵심 콘텐츠 영역을 명확히 지정하고, 스크린 리더 사용자가 콘텐츠에 쉽게 접근할 수 있도록 합니다.
- [ ] **프로그래매틱 포커스 관리**:
    -   화면 전환(예: 페이지 이동) 시 키보드 포커스를 새로운 콘텐츠 영역의 시작(예: `<h1>` 요소)으로 프로그래밍 방식으로 이동시킵니다.
    -   **예시**:
        ```typescript
        const mainHeading = document.querySelector('#content-heading') as HTMLElement;
        if (mainHeading) {
            mainHeading.setAttribute('tabindex', '-1');
            mainHeading.focus();
        }
        ```
- [ ] **ARIA 역할 및 상태 명시**:
    -   Custom Element 컴포넌트가 표준 HTML 역할로 표현하기 어려운 경우, `role`, `aria-*` 속성을 사용하여 보조 기술에 역할과 상태를 명확히 전달합니다.

### 4. 빌드 프로세스 및 성능 최적화

- [ ] **이미지 최적화 자동화 도입**:
    -   빌드 스크립트(`css-prod`, `html-prod` 등)에 이미지 압축 및 WebP와 같은 최신 포맷으로 자동 변환하는 단계를 추가합니다 (예: `sharp` 라이브러리 활용).
    -   **기대 효과**: 이미지 파일 크기 감소, 페이지 로딩 속도 향상, 사용자 경험 개선.
- [ ] **CSS Critical Path 최적화 고려**:
    -   각 페이지의 첫 화면 렌더링에 필수적인 CSS를 HTML 파일의 `<style>` 태그 안에 직접 삽입하고, 나머지 CSS는 비동기적으로 로드하는 전략을 고려합니다.
    -   **기대 효과**: 초기 렌더링 시간 단축.

**결론**: `book-world` 프로젝트는 견고한 기반을 가지고 있습니다. 위의 제안들은 성능, 유지보수성, 접근성을 더욱 향상시켜 사용자에게 더 나은 경험을 제공할 것입니다. 특히 **HTML 템플릿 인라이닝**, **중앙 집중식 스토어 도입**, **이미지 최적화**는 우선적으로 고려해 볼 만한 과제입니다.
